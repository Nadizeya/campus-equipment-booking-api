## Scope and conventions

The API lists equipment and manages bookings. Authentication and equipment editing are outside the exam's required scope. Requests to POST/PATCH use `Content-Type: application/json`. All responses with bodies are JSON; DELETE success has no body. IDs are opaque strings; booking IDs are generated by the server.

The exam specifies endpoints, fields, success statuses, and the error format. The choices below settle unspecified behavior and are implementation assumptions rather than additional instructor requirements:

- Lists return arrays, including `[]` for no results. Equipment sorts by `id`; bookings sort by start time, then `id`, ascending.
- POST requires exactly the five writable fields below. PATCH accepts one or more of those fields, including a full payload, and validates the merged booking.
- Reject unknown fields, an empty PATCH, `null`, arrays, and non-object payloads with `400`. `id` is not writable.
- Trim surrounding whitespace from equipment IDs, borrower names, and purposes; reject empty values and non-string values.
- Timestamps must be valid calendar date/times in ISO 8601 form `YYYY-MM-DDTHH:mm:ss[.SSS](Z|±HH:mm)`, with zero to three fractional digits and an explicit timezone. Reject impossible dates rather than silently normalizing them. Return normalized UTC values with three fractional digits.
- Allow past dates; the exam imposes no future-only booking rule.
- Treat reservation intervals as `[startAt, endAt)`, allowing adjacent bookings.
- An unknown equipment ID in a payload is `400`; a missing booking addressed by URL is `404`.
- For PATCH, check booking existence first, then validate the payload and merged values, then check conflicts. For POST, validate data before checking conflicts.
- Failed writes leave stored data unchanged.

## Resource shapes

Equipment object:

```json
{ "id": "eq-1", "name": "Projector A", "location": "Building 1" }
```

Booking create payload (all fields required):

```json
{
  "equipmentId": "eq-1",
  "borrowerName": "Somchai Jaidee",
  "startAt": "2026-10-20T09:00:00.000Z",
  "endAt": "2026-10-20T11:00:00.000Z",
  "purpose": "Class presentation"
}
```

Booking response:

```json
{
  "id": "example-booking-id",
  "equipmentId": "eq-1",
  "borrowerName": "Somchai Jaidee",
  "startAt": "2026-10-20T09:00:00.000Z",
  "endAt": "2026-10-20T11:00:00.000Z",
  "purpose": "Class presentation"
}
```

| Writable field | Type | Validation |
|---|---|---|
| equipmentId | string | Non-empty; equipment record must exist |
| borrowerName | string | Non-empty after trimming |
| startAt | string | Valid timestamp with timezone |
| endAt | string | Valid timestamp with timezone; strictly after startAt |
| purpose | string | Non-empty after trimming |

## Endpoints

Paths are relative to the base URL.

| Method | Path | Success status/body | Errors |
|---|---|---|---|
| GET | `/equipment` | `200`, equipment array with at least two seeded records | `500` for unexpected failure |
| GET | `/bookings` | `200`, booking array | `500` for unexpected failure |
| GET | `/bookings/:id` | `200`, booking object | `404` if missing; `500` for unexpected failure |
| POST | `/bookings` | `201`, persisted booking object | `400` invalid input; `409` conflict; `500` unexpected failure |
| PATCH | `/bookings/:id` | `200`, persisted updated booking object | `404` missing booking; `400` invalid input; `409` conflict; `500` unexpected failure |
| DELETE | `/bookings/:id` | `204`, empty body | `404` if missing; `500` for unexpected failure |

Partial PATCH example:

```json
{ "purpose": "Updated presentation" }
```

Unspecified fields keep their current values. Validate the entire merged record, including equipment and both times. When changing equipment, check reservations for the new equipment. Exclude the current booking ID from overlap checks.

## Conflict rule

A reservation conflicts when another booking has the same equipment ID and both comparisons are true:

```text
existing.startAt < requested.endAt
existing.endAt > requested.startAt
```

Compare numeric instants, not raw timestamp strings with different timezones.

| Existing reservation | Requested reservation | Same equipment? | Result |
|---|---|---|---|
| 09:00–11:00 | 10:00–12:00 | Yes | `409` |
| 09:00–11:00 | 09:30–10:00 | Yes | `409` |
| 09:00–11:00 | 08:00–12:00 | Yes | `409` |
| 09:00–11:00 | 09:00–11:00 | Yes | `409` |
| 09:00–11:00 | 11:00–12:00 | Yes | Allowed |
| 09:00–11:00 | 08:00–09:00 | Yes | Allowed |
| 09:00–11:00 | 10:00–12:00 | No | Allowed |

Times in this table refer to the same date and timezone. A purpose-only edit of an existing booking must succeed without conflicting with itself.

## Errors

Every error response uses this envelope:

```json
{ "error": "A message understandable to a user or developer" }
```

| Status | Reason | Example message |
|---|---|---|
| 400 | The request cannot form a valid booking | `startAt must be before endAt` |
| 400 | Malformed JSON | `Request body must be valid JSON` |
| 400 | Referenced equipment does not exist | `equipmentId must reference existing equipment` |
| 404 | The addressed resource is absent | `Booking not found` |
| 409 | Valid booking data conflicts with existing state | `Equipment is already booked during this time` |
| 500 | Unexpected internal failure | `Internal server error` |

These example messages guide implementation; tests should assert status, envelope, and understandable meaning rather than require every example's exact wording. Unknown routes also return a JSON `404`. Do not expose SQL, stack traces, or internal exception details to clients.
